# Research Skill Hub

一个本地运行的科研 Skill 信息导航站。订阅公开 GitHub 来源，按 **Search → Read → Reason → Experiment → Write** 分类浏览、搜索与收藏。

应用只采集介绍信息，不下载、安装或执行 Skill，不调用模型或翻译 API。数据保存在本机 SQLite 中，断网时仍能浏览和人工整理。

## 启动

需要 [uv](https://docs.astral.sh/uv/)。在项目目录运行：

```bash
uv sync
uv run skill-hub
```

访问 **http://127.0.0.1:8765**。按 `Ctrl+C` 停止。Python 3.12 是验证基线，`.python-version` 已指定版本，uv 会在需要时安装。依赖版本固定在 `uv.lock`；无需 Node、Docker 或模型账户。

默认仅监听回环地址、单进程、单 worker，不使用 `--reload`。同一数据目录的第二个实例会被拒绝。已验证 macOS；采用 `fcntl` 文件锁，也适用于 Linux，Windows 原生运行尚未支持。

### 可选配置

复制 `.env.example` 为 `.env`，按需修改：

```dotenv
SKILL_HUB_HOST=127.0.0.1
SKILL_HUB_PORT=8765
SKILL_HUB_DATA_DIR=./data
GITHUB_TOKEN=
```

`GITHUB_TOKEN` 可选，仅用于公开仓库的 GitHub API 读取。无 Token 也能启动并尝试采集；实际限额以 GitHub 响应为准。遇到限流，来源页显示原因和最早重试时间，无需反复点击。Token 不写入数据库、网页或日志，不发送给 Raw 主机。`.env`、数据库、虚拟环境均被 Git 忽略。

数据库为 `data/hub.sqlite3`，相对数据目录按启动时的工作目录解析。更换启动目录时请指定绝对 `SKILL_HUB_DATA_DIR`。备份时先停止服务，再复制整个数据目录；不提供网页导出接口。应用日志输出到启动终端，不保存原始请求、上游全文或认证信息。

## 使用

- **首次刷新**：四个预置来源只在空库初始化时导入。页面立即可用，启用来源在后台串行采集；数据逐步入库，完成后页面自动刷新。
- **检索与筛选**：中英文关键词匹配名称、原始介绍、中文简介及标签；可按主分类、来源、领域、收藏、精选筛选。卡片顶部显示主分类，其他阶段能力以“辅助：检索”等标签展示。筛选和排序保存在 URL，默认每页 24 项。
- **收藏与精选**：星标用于收藏，详情中可以设置精选。精选仅代表个人选择。
- **人工分类与简介**：打开“详情 / 编辑”，修改主分类、辅助分类、中文简介、标签、领域、使用条件或备注。自动刷新只更新上游和自动字段，保留人工字段。
- **恢复自动值**：每个可覆盖字段旁有“恢复自动”。点击后保存即清除该覆盖；直接把内容删空并保存会保留一个“空值覆盖”。二者含义不同。
- **添加来源**：在来源页输入 `owner/repo` 或 HTTPS GitHub 仓库根 URL，并填写扫描目录或精确 `SKILL.md` 路径；扫描路径每行一个。支持分支配置，留空使用仓库默认分支。
- **修改来源**：编辑名称、扫描范围、分支、周期和备注。仓库是来源身份，添加后不可改为另一个仓库；需要迁移时添加新来源并停用旧来源，避免混合两仓库资料。
- **定时刷新**：每个来源支持关闭、每 24 小时、每 7 天。周期 0 只关闭自动刷新，仍可手动刷新。停用来源不参加自动刷新或“刷新全部”；仍可明确刷新该来源。
- **停用来源的资料**：保留在数据库，目录默认隐藏，可勾选“显示停用来源”。
- **依据和案例**：可手动保存官方演示、作者报告、第三方案例或待核实链接。应用不抓取这些外部链接，也不自动确认机构身份、采用情况或许可结论。

### 刷新状态与恢复

手动和定时刷新共用一个队列，已排队或正在执行的来源返回同一个任务，不重复执行。任务状态包括排队中、更新中、完成、部分完成、失败和未完成；最近保留 200 条记录，页面显示最近 30 条。

一次同步使用固定 commit。未变化的文件跳过正文读取；失败条目即使 SHA 不变也会重试。仅仓库 Stars/Forks 变化不会改变 Skill 的信息更新时间。Stars 是所属仓库指标，未知显示“未知”。

文件树截断时补取子树，无法补全则报告部分完成。个别文件失败时保留已有资料。只有完整枚举且扫描范围与前次一致时才标记上游缺失；不删除条目。网络失败和限流会延后重试，普通失败默认等待 15 分钟。

应用停止或电脑休眠时不会刷新。重启将遗留任务标记为未完成，到期的启用来源最多补一次，不补跑所有错过周期。在任务运行中修改来源配置，当前任务使用启动时的配置快照，下次任务使用新配置。

## 分类与中文简介

规则位于 `config/classification_rules.yaml`，当前条目的核对映射位于 `config/classification_catalog.yaml`。优先级为：人工覆盖 > 来源与内容限定的已核对映射 > 名称/介绍关键词 > 待分类。按主要任务选择一个主分类，兼有的任务放入辅助分类，学科领域单独标注。详见 [分类规则说明](docs/CLASSIFICATION.md)。

关键词会统一大小写、连字符和下划线，优先匹配名称和介绍首句，降低附带用途的权重，并排除常见否定用途。规则生成的中文标签与具体中文简介分开保存；任务冲突或原始介绍变化会提示复核。安装、部署、开发及科研事务辅助条目保留可见，加上辅助标签，不强制归入五个科研阶段。

初版维护 11 条基于 2026-09-15 真实采集介绍核对的中文简介，其他条目显示原始介绍与“暂无中文简介”。精确映射不会创建条目，也不会套用于其他仓库的同名 Skill。API Key 和付费状态在没有可靠结构化判断时保持“未确认”，可由用户根据原文修正。

修改规则后运行 `uv sync` 并重启应用，启动时自动用本地已保存的介绍重新分类，无需刷新 GitHub。更新前自动备份数据库到 `data/backups/`，只修改自动分类字段及信息更新时间；收藏、精选、人工覆盖、备注、证据和采集状态保持原值。解析器版本变更仍由下次来源刷新重新获取介绍文件。

## 验证

```bash
uv run pytest
uv run ruff check .
```

普通测试使用明确标记的 fixture 与 HTTP mock，无需外网、Token 或模型。覆盖解析、分类、缓存、限流、增量更新、人工覆盖、调度去重、安全输入、路由渲染和完整编辑闭环。

真实网络验收单独运行，**先停止正在运行的服务**：

```bash
uv run python -m scripts.smoke_sync
```

该命令使用当前配置的数据目录，先刷新 Docling 精确文件，再刷新 DeepMind 的 skills 目录，输出实际任务统计。不会注入测试数据。执行结果见 [验收记录](docs/VALIDATION.md)。

### 本地安装说明

项目在安装包中显式包含源码、页面和默认配置；`pyproject.toml` 中的缓存配置 根据源码、模板、静态文件及规则变化重建安装。这避免部分 macOS 环境给 `.pth` 文件设置隐藏标记后导致命令入口无法导入包。正常仍使用上述 `uv sync` 与 `uv run` 命令。

## 项目结构

```text
config/                  预置来源和分类规则
skill_hub/
  main.py                生命周期、本地安全边界与启动入口
  db.py                  SQLite 表、查询与人工覆盖展示
  github_source.py       GitHub 只读采集、快照、目录与限流
  parser.py              有界安全 YAML 与介绍提取
  classifier.py          确定性分类与中文映射
  sync_service.py         增量更新和单执行器
  scheduler.py           到期检查
  routes.py              本地页面与内部接口
  templates/ static/     中文界面，无 CDN
scripts/smoke_sync.py     可选真实网络验收
tests/                   离线测试
```

## 已知限制与后续范围

- 服务必须保持运行才能定时刷新，未配置开机自启。
- 当前目录检索在内存中筛选 SQLite 读出的条目，适合个人收藏规模；不引入全文检索服务或向量数据库。
- 介绍文件最大 256 KiB，API 响应最大 8 MiB，目录枚举最多 300 次树请求、深度 30；超限如实报告未处理或部分完成。
- GitHub 重定向会被拒绝并提示修正仓库，不自动追随改名后的地址。
- 上游格式不完整会显示兜底介绍并进入部分完成状态；自动规则不能保证分类准确，用户可修正。
- 未实现 P1：通用网页/RSS 采集、自动发现来源、模型翻译与分类、讨论热度、第三方采用验证、相似 Skill 合并、消息推送。
- 不提供下载、安装、执行 Skill、多用户、云部署或文件导出接口。

完整范围见 [MVP 需求](docs/SKILL_HUB_MVP_SPEC.md)。
